# Otto: general computer-use architecture research

Source comparison, 2026-09-19 UTC. Findings describe inspected source and authors’ reports, not independent benchmark reproduction. Otto was inspected at `1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52`; descriptions of its implementation below refer to that revision.

**Recommendation:** first remove the action/observation ceiling, then benchmark a Jev-controlled observation and reasoning budget against the same general controller without Jev. “Jev + computer use,” hybrid DOM/vision, and verified actions already have close prior art. A defensible contribution would be equal-or-better task success at demonstrably lower total cost, latency, and user intervention—not a novel combination claim.

## What the reference implementations actually do

### Cua: reusable driver beneath an agent harness

Pinned [Cua commit `83f142c`](https://github.com/trycua/cua/commit/83f142c4290a0f7d9ed545ae8532858c6e4f8145), dated 2026-09-18. Its current boundary is useful for Otto: the model/harness chooses actions and recovery; the driver supplies native/browser execution and evidence. It is not itself proof of superior planning.

The macOS [`get_window_state` implementation](https://github.com/trycua/cua/blob/83f142c4290a0f7d9ed545ae8532858c6e4f8145/libs/cua-driver/rust/crates/platform-macos/src/tools/get_window_state.rs#L25-L118) returns structured AX elements and screenshot geometry, scopes identity to PID/window, and rejects mismatches. Callers can omit screenshots or AX, query a projected subtree, and bound depth, element count, or image dimensions. Those are concrete mechanisms for adaptive observation budgets. Missing AX can return a degraded result with the correctly scoped image rather than blocking all progress. Actions include semantic and pixel routes, menus, hotkeys, drag, browser tools, and window operations.

Cua explicitly separates **action delivery/effect** from **task postconditions**. [`ActionResult` and verification contracts](https://github.com/trycua/cua/blob/83f142c4290a0f7d9ed545ae8532858c6e4f8145/libs/cua-driver/docs/action-result-contract.md) preserve `unverifiable`, `suspected_noop`, and `unknown`; escalation is advice to the harness, not an automatic replay. That distinction is directly reusable as a design principle. Its [platform evidence ledger](https://github.com/trycua/cua/blob/83f142c4290a0f7d9ed545ae8532858c6e4f8145/libs/cua-driver/docs/action-support.md) records both delivered actions and expected refusals. Passing a refusal test is not successful execution; background Electron/SwiftUI and Windows paths have material limitations. Evaluate candidate drivers on Otto’s actual target apps before migration.

**Especially close prior art:** Cua’s [`jev-use`](https://github.com/trycua/cua/blob/83f142c4290a0f7d9ed545ae8532858c6e4f8145/libs/cua-driver/examples/jev-use/README.md#L3-L58) selects immutable candidates using Jev, reserves reobserve/abstain, binds browser/visual targets to snapshots, and checks an independent fixture state endpoint. The optional visual adapter is capability-gated; its presence does not prove every released driver provides that capability. The [validation report](https://github.com/trycua/cua/blob/83f142c4290a0f7d9ed545ae8532858c6e4f8145/libs/cua-driver/docs/jev-use-validation.md) reports Mac live-provider setup proofs and unresolved Windows/Linux environment prerequisites—not a general task benchmark.

### Agent S3: flat visual policy, grounding, reflection, optional code delegation

Pinned [Agent-S commit `3aa272d`](https://github.com/simular-ai/Agent-S/commit/3aa272d23d2994c7bbde1acbbe0ef8e8d06b8693), dated 2026-09-05. [`AgentS3`](https://github.com/simular-ai/Agent-S/blob/3aa272d23d2994c7bbde1acbbe0ef8e8d06b8693/gui_agents/s3/agents/agent_s.py#L48-L94) is intentionally a flat worker rather than a manager hierarchy. The worker reasons over screenshots, action history, notes, and optional reflection. A separate [grounding model](https://github.com/simular-ai/Agent-S/blob/3aa272d23d2994c7bbde1acbbe0ef8e8d06b8693/gui_agents/s3/agents/grounding.py#L229-L283) turns referring expressions into coordinates; OCR also supports text selection. Its action surface includes click, typing, drag, hotkeys, wait, and conditional code-agent delegation.

The [worker](https://github.com/simular-ai/Agent-S/blob/3aa272d23d2994c7bbde1acbbe0ef8e8d06b8693/gui_agents/s3/agents/worker.py#L63-L176) retains eight recent image turns by default, preserving text for supported long-context models; other engines drop older full turns. Reflection evaluates the prior action in the new screenshot. Malformed action conversion waits rather than executing arbitrary malformed output. Code delegation is hidden if no environment controller exists—desktop support does not imply identical capabilities on every platform.

Evidence: [*Scaling Agents for Computer Use*, v2, 2026-02-03](https://arxiv.org/html/2510.02250v2) reports 72.6% OSWorld at 100 steps with Behavior Judge selecting among multiple rollouts. The [repository](https://github.com/simular-ai/Agent-S/blob/3aa272d23d2994c7bbde1acbbe0ef8e8d06b8693/README.md#L108-L119) distinguishes approximately 66% single-agent performance from this ensemble result. These are author-reported benchmark results, not proof that the current source plus arbitrary model reproduces them. The newer hosted Sai score is a different product/benchmark and cannot be transferred to this OSS stack. Best-of-N also requires resettable isolated environments; parallel alternatives must not mutate the same personal desktop.

### UI-TARS / Agent TARS: visual loop plus browser/tool routing

Pinned [UI-TARS-desktop commit `c2ad42e`](https://github.com/bytedance/UI-TARS-desktop/commit/c2ad42e3eb9b27830db41a3e6f51ca7179d9b168), dated 2026-07-01. Its [GUIAgent loop](https://github.com/bytedance/UI-TARS-desktop/blob/c2ad42e3eb9b27830db41a3e6f51ca7179d9b168/packages/ui-tars/sdk/src/GUIAgent.ts#L130-L413) repeatedly screenshots, calls a GUI model, parses actions, executes an operator, and observes again; pause/abort/loop limits and separate screenshot/model/execution retry hooks exist. Execution retry is configurable, not a safe default to copy for ambiguous side effects. [Image context trimming](https://github.com/bytedance/UI-TARS-desktop/blob/c2ad42e3eb9b27830db41a3e6f51ca7179d9b168/packages/ui-tars/sdk/src/utils.ts#L58-L87) drops older images while preserving other conversation content.

Agent TARS is the broader tool harness: its [hybrid browser strategy](https://github.com/bytedance/UI-TARS-desktop/blob/c2ad42e3eb9b27830db41a3e6f51ca7179d9b168/multimodal/agent-tars/core/src/environments/local/browser/browser-control-strategies/browser-hybrid-strategy.ts#L10-L58) exposes GUI grounding alongside DOM click/fill/hover/select/tab tools and content/navigation tools. This is an implemented hybrid action surface, not evidence the policy chooses efficiently. The [original UI-TARS paper, 2025-01-21](https://arxiv.org/abs/2501.12326) describes screenshot-native training and historical benchmark results; those scores are model/version-specific and are not current SOTA evidence for this desktop app.

## Closer product competitors

[jev-browser](https://github.com/jkudish/jev-browser/tree/8d90c51bedbe7cd07596bfaa532ded019a31d2a8) (HEAD resolved during this review) already uses Jev for action choice plus goal/stuck judgments, with a small optional generator for typing and code-owned budgets/recovery. Its README documents dense-page truncation and unsupported interactions; published tiny navigation demos are not broad reliability results.

[Kortix agent-computer-use](https://github.com/kortix-ai/agent-computer-use/tree/9c58747c1cac78adcc33e606f1244c995dedacd8) supplies a native AX/UIA/AT-SPI CLI with Electron CDP. Its “zero per-action cost” refers to local tool execution, not the agent’s reasoning, tokens, or failures. README labels platform support preview. These two sources received a bounded README review, not a full implementation audit.

## Otto’s ceiling at the inspected revision

- [`core/candidates.ts:16–188`](https://github.com/NobleSpartan6/otto/blob/1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52/core/candidates.ts#L16-L188): at most 64 lexically ranked candidates; press, exposed fill/vertical-scroll, existing-app activation, Enter/Escape/Tab, finish/blocked. No general hover, drag, right-click, hotkey chord, file/dialog/browser primitive, or model-grounded visual target.
- [`core/planner.ts:248–367`](https://github.com/NobleSpartan6/otto/blob/1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52/core/planner.ts#L248-L367): optional screenshot helps choose an existing candidate only; it cannot introduce a missing target/action. History is the last 20 action/change entries, not a durable task/evidence memory. Stronger vision alone cannot solve this ceiling.
- [`core/engine.ts`](https://github.com/NobleSpartan6/otto/blob/1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52/core/engine.ts#L442-L608): 20 decisions, five planner calls, ten minutes, four preselected apps, every-action approval. Stalls mean three repetitions with unchanged aggregate state; unrelated UI changes can mask stagnation. The 0.55 confidence escalation threshold is not task-calibrated evidence.
- [`desktop/native-driver.ts`](https://github.com/NobleSpartan6/otto/blob/1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52/desktop/native-driver.ts#L171-L229) + [`ocr.ts`](https://github.com/NobleSpartan6/otto/blob/1ba20cdb026c92d7fbef343a874c9d3ad1e9eb52/desktop/ocr.ts#L33-L107): OCR adds at most 50 English text-line click targets, not visual object grounding. Mac AX walk caps 180 controls/1,200 visited nodes/depth 18. Good stale-target guards should be retained, but coverage is narrow. A snapshot change or API acceptance is not a task outcome.

## Three architectures to benchmark

| Architecture | Execution / observation policy | What it tests |
| --- | --- | --- |
| **A. General visual baseline** | Flat planner each step; screenshot grounding; full typed pointer/keyboard actions; reflection on failures; identical native scope/approval policy. Agent-S-style control without Jev. | Whether general visual coverage actually solves Otto’s missing-target tasks; establishes latency/cost/success baseline. |
| **B. General semantic-first hybrid** | Same planner and driver, AX/DOM first; deterministic rules escalate to screenshots/visual grounding on absent targets, degraded observations, or failed postconditions. Compact task ledger and recent images. No Jev. | How much improvement comes from richer tools and straightforward routing rather than Jev. |
| **C. Adaptive Jev hybrid** | Same tools, planner, permissions, and ledger as B. Jev selects bounded observation requests and execution routes, and predicts whether more evidence/reasoning is useful; generator handles open-ended planning/text. Deterministic evidence controls success. | Whether learned budget allocation beats fixed rules at matched success, intervention, and total cost. |

Start with B as the product foundation and C as the research hypothesis. Jev should allocate **information and reasoning**, not merely classify an already expensive full observation. Query small subtree → larger subtree/DOM → region/crop → full image → planner is a measurable policy; allow abstention and budget exhaustion. Retain raw evidence outside prompt memory and a compact ledger of goal, subgoals, constraints, completed facts, failed attempts, and unresolved uncertainty. Keep one executor per interactive desktop; delegate independent research or computation through separate scoped workers.

Use paired tasks with fresh states and identical model/version/budget/approval rules, including native menus/dialogs, inaccessible canvas/Electron, scrolling, multiple apps, generated text, interruptions, and deliberate ambiguous effects. Score independently verified end states; report success, false completion, retries, human interventions, p50/p95 latency, provider tokens/cost, native observation time, and screenshot volume. Add C ablations for fixed thresholds, no Jev, and action-only Jev. Count all failed requests and unknown usage honestly. A narrow result such as “lower median cost at matched verified completion on this published Mac/Windows suite” could be defensible. “Best computer-use agent” is unsupported until comparable external benchmark results exist.
